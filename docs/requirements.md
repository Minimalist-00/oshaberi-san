# トークテーマガチャアプリ 要件定義書

## 概要

こーきとみずきが日常で思いついた「話したいこと」を、話す時まで見えないようにストックしておき、話す直前にガチャ演出でランダムに引き当てるWebアプリ。

| 項目 | 内容 |
|------|------|
| フレームワーク | Next.js（Page Router） |
| スタイリング | Tailwind CSS |
| フェーズ1（開発・テスト） | localStorage。Mac ブラウザで動作確認 |
| フェーズ2（本番） | Supabase に移行。2人のスマートフォンからデータ同期 |

---

## 開発フェーズ

### フェーズ1：ローカルストレージ版（現在のスコープ）

- Mac のブラウザ上で動作確認
- データは `localStorage` に保存（端末単体で完結）
- `lib/storage.ts` に CRUD 処理を集約し、**上位レイヤー（画面・コンポーネント）はストレージの実装を知らない設計**にする
- 認証なし。セッション中のユーザーは `sessionStorage` で管理

### フェーズ2：Supabase 版（将来）

- `lib/storage.ts` の実装を Supabase SDK に差し替えるだけで移行完了
- 画面・コンポーネントのコードは変更不要
- こーき・みずきそれぞれのスマートフォンからリアルタイムにデータ同期
- Supabase Auth でユーザー認証を追加（メール or Google ログイン）
- Row Level Security（RLS）でデータアクセスを制限

**移行時の追加作業:**
1. Supabase プロジェクト作成・テーブル作成（`TalkTheme` 型をそのままカラムにマップ）
2. `lib/storage.local.ts` → `lib/storage.supabase.ts` に差し替え
3. トップページのユーザー選択 → Supabase Auth のログイン画面に変更
4. 環境変数（`.env.local`）に Supabase の URL・API キーを追加

## 画面詳細

### 1. トップページ（`/`）

**目的:** セッション開始時のユーザー識別

**UI要素:**
- アプリ名・キャッチコピー
- ユーザー選択ボタン × 2（こーき / みずき）

**動作:**
- ボタン押下 → `sessionStorage` にユーザー情報を保存
- `/input` にリダイレクト

> フェーズ2では、このページを Supabase Auth のログイン画面に差し替える。

---

### 2. テーマ入力画面（`/input`）

**目的:** 思いついたトークテーマをその場でメモする

**UI要素:**
- 現在のユーザー表示（例：「こーきとしてメモ中」）
- テキストエリア（テーマ本文）
- 送信ボタン
- 「ガチャ画面へ」ナビゲーションリンク

**動作:**
- 送信時、以下のデータを保存する
  - `id`: UUID（自動生成）
  - `text`: テーマ本文
  - `author`: 現在のユーザー名
  - `created_at`: 入力日時（ISO 8601）
  - `status`: `"pending"`
- 保存後はフォームをリセットし、成功トーストを表示

**備考:**
- フェーズ1では localStorage のためデータは端末内に閉じる。テーマ本文の非表示制御は実装しない（同じ Mac で操作する前提）
- フェーズ2では Supabase + RLS によりログインユーザーのみ自分のデータを取得可能になる

---

### 3. ガチャ画面（`/gacha`）

**目的:** ストック中のテーマをランダムに引き当て、話し済みにする

**UI要素:**
- 残りテーマ件数（「残り ○ 件」）
- ガチャボタン（「引く！」）
- 演出エリア（ブルブル振動 → デデン！のフェードイン）
- 引き当てたテーマカード
  - テーマ本文
  - 入力者名（例：「これはみずきのテーマです」）
  - 入力日
- 操作ボタン
  - 「次の話題へ」：現在のテーマを完了にして次をガチャ
  - 「やめる」：現在のテーマを完了にしてトップへ戻る

**動作:**
1. `status: "pending"` のテーマからランダムに1件選択
2. ガチャアニメーションを再生（ブルブル → フェードイン）
3. テーマカードを表示
4. **ガチャで引いた瞬間に `status: "done"` フラグが立つ**（「次へ」「やめる」どちらを押しても同じ扱い）
5. 「次の話題へ」→ `done_at` を記録して次のガチャへ
6. 「やめる」→ `done_at` を記録してトップへ遷移

**エッジケース:**
- ストックが0件 → 「テーマが登録されていません」を表示し、入力画面へ誘導

---

### 4. 過去のトーク（`/archive`）

**目的:** 話し済みテーマの振り返り

**UI要素:**
- テーマカード一覧（`status: "done"` のもの、新しい順）
  - テーマ本文
  - 入力者名（「こーきのテーマ」/ 「みずきのテーマ」）
  - 入力日
  - 完了日

---

## データモデル

```typescript
// lib/types.ts

type Author = "こーき" | "みずき";

type TalkTheme = {
  id: string;           // UUID
  text: string;         // テーマ本文
  author: Author;       // 入力者
  created_at: string;   // ISO 8601（入力日時）
  status: "pending" | "done";
  done_at?: string;     // ISO 8601（完了日時。ガチャで引いた瞬間に記録）
};
```

---

## ストレージ抽象レイヤー設計

画面・コンポーネントはこのインターフェースだけを呼ぶ。実装（localStorage / Supabase）は内部で差し替え可能。

```typescript
// lib/storage.ts が公開するインターフェース

getThemes(): Promise<TalkTheme[]>
addTheme(input: { text: string; author: Author }): Promise<TalkTheme>
markAsDone(id: string): Promise<void>
getPendingThemes(): Promise<TalkTheme[]>
getDoneThemes(): Promise<TalkTheme[]>
```

| ファイル | 役割 |
|----------|------|
| `lib/types.ts` | 型定義 |
| `lib/storage.ts` | インターフェース・エクスポート |
| `lib/storage.local.ts` | フェーズ1：localStorage 実装 |
| `lib/storage.supabase.ts` | フェーズ2：Supabase 実装（後で追加） |

## 非機能要件

- **レスポンシブ対応:** スマートフォン操作を主として設計（フェーズ1の確認は Mac ブラウザで可）
- **アニメーション:** CSS アニメーション or Framer Motion でガチャ演出を実装
- **型安全:** TypeScript で全体を記述
